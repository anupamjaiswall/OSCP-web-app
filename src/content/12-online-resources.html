🧰 22.7 Local-First Lookup — Prefer This for Sensitive Material

[ONLINE:SAFE-USE] [HASH:LOCAL]

  • Hash identification/examples: use local hashid, hashcat --example-hashes, hashcat -m ... documentation, or John locally rather than uploading captured hashes.
  • Encoding/decoding: use local shell/Python or a locally available CyberChef instance where possible. If using a public web utility, do not paste exam secrets.
  • Tool syntax: installed tool -h / tool --help is the authority for the exact version on your Kali box.
  • Error research: search the exact error plus the tool/protocol name; do not include target IPs, usernames, flags, credentials or other exam-specific identifiers.

Convert a reference into an OSCP-safe next action

1. OBSERVE: record the port, service, identity, permission or exact error.
2. HYPOTHESIZE: choose one plausible path from the reference.
3. CHECK PREREQUISITES: versions, rights, reachability, configuration and tool availability.
4. VALIDATE: run the smallest non-destructive, in-scope check first.
5. PROVE: capture command/output and the resulting access or privilege.
6. RE-ENUMERATE: new credential or access? Revisit relevant services and AD edges.
7. PARK: if prerequisites are absent or the path is speculative, log it and move on.

AD reminder: a mindmap is a branch checklist, not a linear exploit recipe. For each candidate edge, record the source principal, target object, required right, evidence, validation command and outcome. Do not assume every branch is available in the exam environment.

Exam boundary: pre-exam browsing is for preparing notes. During the exam, follow the current OffSec Exam Guide, FAQ and Control Panel; do not use prohibited automation or AI features, and never upload target secrets or evidence to third-party sites.
