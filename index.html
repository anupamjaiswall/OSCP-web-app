I have this — what next?

Only an IP

Full TCP scan, quick focused scan in parallel, then targeted UDP when the host role justifies it. Save raw output.

A port or service

Use the native client. Test anonymous/default/known credentials and record access, role, data and the next manual proof.

A web application

Hostname/vhosts, source, headers, cookies, robots, sitemap, JavaScript, network calls, content, backups and exposed .git before exploit hunting.

A version banner

Confirm access context, exact build/package, architecture, configuration, trigger and patch/backport status. Version alone is not a vulnerability.

A credential or hash

Record its source, test it across appropriate known services, distinguish authentication from authorization, and respect lockout policy.

A Linux shell

Stabilize; sudo, SUID, capabilities, cron/systemd, services, secrets, containers and internal listeners. Kernel/CVE last.

A Windows shell

Identity/privileges, files/software, services, tasks, registry, credentials, DLL/path, local ports and custom apps. Kernel last.

A domain credential

Fix DNS/time, validate SMB/LDAP/WinRM/RDP, enumerate shares and Kerberos, collect BloodHound (RustHound-CE is a collector option), check AD CS, then follow one proven edge.

A new network or route

Prove pivot-host reachability, create one tunnel/route, enumerate the internal surface, and repeat the same target loop.

Root / SYSTEM / Administrator

Stop. Capture the flag from its original location in an interactive shell with the target IP visible, submit it, then protect the report evidence.

Stuck right now — three-minute reset

Stop random actions. Preserve the state, name the missing prerequisite, run one decisive check, then continue or rotate.

No initial access

Re-read every service result; revisit vhosts, source/JS, anonymous/default access, files/backups and credential reuse before another CVE.

Shell, no escalation

Re-check identity and privileges. Rank writable privileged execution, credentials and internal-only services above kernel exploits.

Credential fails

Separate authentication from authorization; fix domain/user format, DNS/time and protocol. Check lockout risk before retrying.

Pivot is broken

Prove reachability from the pivot host, then verify tunnel session, route and connection direction.

Tool is failing

Read the error and local help, make one native/manual request, then try one alternate implementation only.

Root / SYSTEM reached

Stop exploitation. Capture proof + IP in the interactive shell, submit the flag, and finish report notes now.

Best OSCP Methodology

Evidence first. The output of each step decides the next step.
Alt MREPEATABLE

Prepare and scope

Create one target folder, confirm VPN/route and target identity, start command logging, and write the expected evidence filenames.

Map the attack surface

Run a full TCP scan first, then focused scripts/versioning on open ports. Add a targeted UDP check when the host or role justifies it. Save every raw result.

Enumerate by service

For every port, answer: what is it, can I access it anonymously/default/with credentials, what data does it expose, and which manual test would prove impact?

Build one testable hypothesis

Write the primitive in one sentence: “Because I observed X, I may be able to do Y.” Rank it by evidence, prerequisites, reliability, time and risk.

Validate prerequisites

Confirm access context, architecture, exact build or package revision, required configuration, authentication level and safe trigger. A version string alone is not proof.

Exploit the smallest reliable path

Before changing a file, ACL, service, task, template or policy, record its original state and rollback command. Use the least complex action that proves the primitive; save public exploit sources, modifications and the exact command.

Stabilize and enumerate locally

Record identity, host, interfaces and privileges; upgrade the shell; enumerate services, scheduled tasks, permissions, secrets, histories and reachable networks.

Escalate or move laterally

Validate one privilege or AD edge at a time. Back up mutable state. After every new credential or identity, test appropriate exposed in-scope protocols with lockout awareness, then re-collect the attack path.

Capture proof immediately

Capture the proof from its original location with target IP and interactive identity visible. Preserve commands, output, exploit changes, screenshots and timestamps. Once closure is complete, write the next action and take a short break if fatigue is rising.

Re-enumerate and close

New access changes the attack surface. Re-run the relevant checks, confirm no reporting gaps, save a session export, then move to the next target.

Kill / park rule

Continue while tests add evidence or raise confidence.

Park after 20–30 minutes or two failed tests with no new evidence. Record the missing prerequisite and the exact return condition.

Priority order

  1. Known credentials and reuse
  2. Anonymous/default access
  3. Readable files, source, backups and secrets
  4. Misconfiguration with a proven primitive
  5. Exact-version exploit with prerequisites
  6. Long brute force or fragile exploit last

Spend ~3 minutes re-anchoring to evidence, then allow at most one 15-minute evidence-producing retry before you rotate.

    

      
1 · BANK FIRST — 20sIf you have local.txt or proof.txt, capture/submit it now. Record the exact path and command before touching anything else.

      
2 · FACTS ONLY — 30sSay the target, ports, access, creds, current user/privileges and last new evidence. Separate facts from assumptions.

      
3 · COVERAGE + LEDGER — 60sFull TCP done? Every exposed service manually touched? Read the Tried / Result ledger: are you repeating a dead branch under a different tool name? Web vhosts/routes/backups? Recovered credentials classified against relevant services? After shell: local listeners, files/config, sudo/SUID/caps or services/tasks/privileges.

6 · ROTATENo new evidence after the timer? Mark the path dead/parked, write why, then move to another service, hypothesis or machine.
