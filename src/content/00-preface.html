↩ TARGET HANDOFF + ACCESS TRUTH LAYER

Why: target rotation fails when the return condition exists only in memory; Windows/AD decisions fail when authentication is mistaken for authorization, command execution, an interactive shell or admin.

Six-line resume / park packet

  1. Current access / identity: exact user, host and channel; say when admin is not proven.
  2. Strongest evidence: one concrete observation that changed the target model.
  3. Exact hypothesis: because I observed X, I may be able to do Y.
  4. Missing prerequisite: the one right, route, build, configuration or trigger still required.
  5. Next decisive command: one command that confirms or rejects the hypothesis.
  6. Re-entry / recovery: the exact shell, tunnel, listener, route or foothold needed to return.

Complete all six fields before parking. The Target view pauses the evidence timer when it parks a target. Use credential labels or environment-variable names only; common password/hash/ticket/private-key patterns are blocked from this packet. After a revert, treat the packet and recorded protocol outcomes as stale until live access is re-established.

Authentication-to-access ladder

OutcomeWhat it provesNext
Not testedNothingOne exact-host request
Transport / service failsRoute, port, hostname, TLS or service issueFix transport before judging credentials
Authentication rejectedThis exact attempt was rejectedCheck identity scope/format, DNS/time and lockout; retry once
Authenticated onlyThe protocol accepted the identityProve one read/query/session action; do not claim admin
Resource / data accessA specific object, share, query or database is readableRecord exact object/path/rights and follow its evidence
Command executionA command ran in one remote contextRecord the token; obtain an interactive session when required
Interactive shell / sessionA usable live session existsBaseline identity/groups/routes/listeners; admin is separate
Privileged / admin controlEffective privileged control was provedBank original-path proof and report evidence immediately

NetExec interpretation: [+] is accepted authentication, not automatic admin. Upstream documents Pwn3d! per protocol—SMB/WMI generally indicate local-administrator capability, while WinRM/RDP indicate at least execution. Validate the actual token and exact action. Command execution is not automatically an interactive proof shell.

# One target + one current principal. Use installed -h/--help as syntax authority.
nxc smb "$TARGET" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN"
nxc ldap "$DC_IP" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN"
nxc winrm "$TARGET" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN"
nxc rdp "$TARGET" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN"
nxc mssql "$TARGET" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN"
nxc wmi "$TARGET" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN"

# Accepted auth only starts the next proof.
nxc smb "$TARGET" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN" --shares
nxc ldap "$DC_IP" -u "$AUTH_USER" -p "$AUTH_PASS" -d "$DOMAIN" --users
evil-winrm -i "$TARGET" -u "$AUTH_USER" -p "$AUTH_PASS"
xfreerdp /v:"$TARGET" /u:"$AUTH_USER" /d:"$DOMAIN" /p:"$AUTH_PASS" /cert:ignore +clipboard
impacket-mssqlclient "$DOMAIN/$AUTH_USER@$TARGET" -windows-auth  # password prompt
impacket-wmiexec "$DOMAIN/$AUTH_USER@$TARGET" "whoami /all"  # password prompt

Never convert this ladder into an indiscriminate spray. Prefer services already observed as exposed and let each result choose the next exact test.

The 10 Rules That Matter Under Pressure

  1. Enumeration is progress only when you read the output. Do not launch ten tools and ignore their findings.
  2. Do not commit to a fixed "AD first" or "standalone first" strategy. After the initial sweep, attack the path with the strongest evidence.
  3. Use a 20–30 minute evidence clock. If you have no new port, credential, file, privilege, hypothesis, or validated vulnerability, rotate.
  4. Every credential is a new attack surface. Test it against all appropriate in-scope services immediately.
  5. Every new shell is a new enumeration phase. Re-run users, privileges, services, internal ports, routes, credentials, scheduled jobs and AD relationships.
  6. Bank points immediately. Capture the official proof screenshot and submit the flag in the control panel as soon as you earn it.
  7. A passing score is not useful if the evidence is invalid. Documentation is part of exploitation.
  8. Break tunnel vision. Recent 2026 passers repeatedly report that short breaks exposed paths they missed while staring at the same machine.
  9. Prefer a validated simple path over an exotic CVE. Exact versions, configuration and prerequisites matter.
  10. Your notes must work without AI. AI/LLM chatbots are prohibited during both the exam and the reporting phase.

What Counts as "New Evidence"?

new credential
new reachable host/port
new virtual host
new writable file/service/task
new BloodHound edge
new group/ACL/delegation right
new internal-only listener
confirmed vulnerable version/config

new application source/config/backup

If none of those changed for 20–30 minutes, you are probably repeating a hypothesis rather than progressing.

💰 Bank the points — 90-second closure gate

[DECISION:PROOF] [EXAM:EVIDENCE]

Do this before another exploit, shell exit, revert or break whenever you obtain local.txt or proof.txt.

  1. Stay in an interactive target shell. PowerShell Core / PSSession counts.
  2. Read the flag with cat or type from its original absolute path; do not use a downloaded, copied or web-shell-displayed flag as proof.
  3. Keep the full flag and target IP from ip addr, ifconfig or ipconfig together in one readable screenshot.
  4. Submit the exact value in the exam control panel before the attack window ends. The panel does not validate correctness, so compare it yourself.
  5. Save the screenshot as <host-or-IP>-<local-or-proof>-original-path.png; record the exact path, commands, output, public-exploit URL and every code change while the shell is still available.
  6. Mark closure complete and write the next action. If fatigue is rising, take a 5–10 minute break now—never before the point is banked.
INTERACTIVE SHELL → ORIGINAL PATH → IP + FLAG IN ONE SCREENSHOT
                  → CONTROL-PANEL SUBMISSION → REPRODUCIBLE NOTES
                  → ONLY THEN MOVE / REVERT / BREAK

At an estimated 70+ points: stop new exploitation long enough to audit every counted target, flag submission and evidence packet.

🛟 Technical-incident / revert gate

[EXAM:INCIDENT] [STATE:STALE]

  • Before calling a target broken, verify VPN interface, route, DNS/time where relevant, packet flow, exact target and one minimal known-good request.
  • The current guide provides a 24-revert bank and allows that bank to be reset once. Record what must be rebuilt, click revert once and wait.
  • A revert destroys target-side changes. Treat prior shells, tunnels, uploads, services/tasks and temporary sessions as stale until revalidated.
  • For infrastructure problems, record timestamps and symptoms and contact the proctor immediately; support cannot provide objective hints.
🧯 Before changing target state — mutation / rollback gate

[STATE:MUTATION] [REQ:SAFE_RECOVERY] [REQ:TRIGGER]

  1. Prove control and trigger: exact principal, permission, privileged consumer and execution/read event.
  2. Capture the original state: path/object, owner, mode/ACL, hash, content, service/task configuration or attribute value.
  3. Protect access and evidence: bank earned flags, keep the shell and write the re-entry path; create a secret-field-free recovery snapshot.
  4. Make the smallest reversible change that proves the primitive.
  5. Write rollback before execution: restore command, backup path, privilege and trigger/restart sequence.
  6. Validate and record: command, result, resulting identity and changed object; restore when practical and revalidate after a revert.
READ ORIGINAL → BACK UP / HASH → WRITE ROLLBACK → MINIMUM CHANGE
              → TRIGGER ONCE → VERIFY → RECORD → RESTORE / REVALIDATE

Allowed against all targets:
  msfvenom
  exploit/multi/handler

Meterpreter itself remains limited to the one selected target.

Responder

The Responder tool itself is listed as allowed, but poisoning and spoofing are not allowed. Therefore, use analyze mode only and do not perform LLMNR/NBT-NS poisoning or spoofing.

Allowed/open-book behavior

  • Nmap/NSE, Nikto, Burp Free/Community, DirBuster and normal manual tools are allowed when they do not perform a restricted action.
  • BloodHound Legacy/CE, SharpHound, PowerView, Rubeus, evil-winrm, Mimikatz, Impacket and PrintSpoofer are listed by OffSec as allowed examples.
  • Online notes/resources are allowed, but do not ask another person/community for exam help.
  • PowerShell Core / PSSession is accepted as an interactive shell.
  • Do not download exam-environment files, applications or source locally unless it is necessary to compromise a target; delete any such local copy after completing the objective.
  • Online guessing is not a default enumeration step: check scope, lockout/rate-limit risk and known usernames first; use an evidence-based shortlist and stop when the signal does not improve.
  • Make every report target/IP unambiguous and verify section order against the control panel; OffSec states that machines are graded and valued in the order documented.
  • Create the final .7z on Kali, visually review the PDF, compare the upload MD5, and click the final Submit File button.
  • All exam activity should be performed on the proctored host.
  • Always re-check the official guide on exam day because tool rules can change.

Most important exam-rule distinction

TOOL NAME ≠ AUTOMATICALLY ALLOWED OR PROHIBITED

Ask:
"What ACTION is this feature performing?"

Five questions before spending >10 minutes on any privilege-escalation idea

1. What exact privileged security boundary am I crossing?
2. Which exact object/permission/configuration gives me control?
3. Can I prove the prerequisite with one command?
4. Can I trigger the privileged behavior?
5. What output proves success or disproves the hypothesis?

If you cannot answer 3 of 5, enumerate more before exploiting.
