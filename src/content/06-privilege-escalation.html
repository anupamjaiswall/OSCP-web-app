⚗ 12.29 Kernel Exploit Decision Rule

Before compiling/running a kernel exploit:

  • [ ] Exact kernel version confirmed
  • [ ] Exact distro/build confirmed
  • [ ] Architecture confirmed
  • [ ] Required kernel feature present
  • [ ] Required module present
  • [ ] Exploit prerequisites satisfied
  • [ ] Mitigations considered
  • [ ] Public PoC/reproducer matches target
  • [ ] Non-kernel paths already checked
  • [ ] Recovery plan exists if the kernel crashes

OSCP rule: a reliable service/configuration privilege escalation is normally preferable to a fragile kernel exploit.

➜ 12.31 Linux Practical Attack Trees --- Finding → Validation → Path

[LINUX:TREE]

Use these after the 60-second pass. The objective is to turn a promising enumeration result into a short, testable hypothesis instead of rereading the entire Linux section.

Priority rule

HIGH    = privileged execution + attacker-writable input + reliable trigger
MEDIUM  = likely privileged execution but one prerequisite still unknown
LOW     = version/CVE match only, noisy theory, or no confirmed trigger

Tree A — sudo -l gives something interesting

sudo -l
  ↓
Exact binary + allowed arguments + user/runas context
  ↓
NOPASSWD? SETENV? wildcard? user-controlled file/path?
  ├─ Standard binary → check GTFOBins behavior for THIS sudo context
  ├─ Script/interpreter → inspect script + imports + called commands
  ├─ Service/package tool → identify privileged action it can invoke
  └─ Restricted args → test whether paths/options can still be influenced
  ↓
Can controlled input reach a privileged execution primitive?
  ├─ YES → validate with a harmless identity/read check first
  └─ NO  → move on; do not force a sudo path that lacks control

Quick checks:

sudo -l
sudo -V | head
command -V <binary>
readlink -f "$(command -v <binary>)"

Tree B — Known SUID/SGID binary

find SUID/SGID
  ↓
Is binary expected on this distro?
  ├─ YES → check known safe/escape behavior (GTFOBins/reference)
  └─ NO  → treat as custom application → Tree C
  ↓
Does effective UID/GID survive the relevant operation?
  ├─ YES → validate minimal privileged capability
  └─ NO  → inspect wrapper/helper/dependencies instead

find / -perm -4000 -type f -ls 2>/dev/nullfind / -perm -2000 -type f -ls 2>/dev/null
ls -l /path/to/binary
file /path/to/binary

Tree C — Custom SUID / privileged custom binary

CUSTOM SUID / ROOT-EXECUTED BINARY
  ↓
file + strings + help/output
  ↓
Trace execution where permitted
  ├─ execs command WITHOUT absolute path → PATH hijack candidate
  ├─ loads writable .so/module/plugin → library/module hijack candidate
  ├─ reads writable config/template → configuration injection candidate
  ├─ writes predictable temp/file → symlink/TOCTOU candidate
  ├─ invokes shell/interpreter → inspect arguments/environment
  └─ processes attacker-controlled file/input → inspect parser/command use
  ↓
Confirm ownership + write permission + privileged trigger
  ↓
Test the smallest controlled behavior
  ↓
If control is proven → use the matching technique; otherwise abandon branch

ls -la /path/to/binary
strings -a /path/to/binary | less
strings -a /path/to/binary | grep -Ei 'system|popen|exec|/bin/|\.so|conf|tmp|python|perl|sh '
readelf -d /path/to/binary 2>/dev/null | grep -E 'RPATH|RUNPATH|NEEDED'
