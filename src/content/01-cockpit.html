C0. THE 20-SECOND OPERATING LOOP

OBSERVATION
    ↓
What does it PROVE?
    ↓
What is the highest-signal NEXT CHECK?
    ↓
Can I validate it in ≤5 minutes?
    ├─ YES → validate
    └─ NO  → park it and enumerate another surface
    ↓
New access / credential / route / privilege?
    ├─ YES → RE-ENUMERATE EVERYTHING RELEVANT
    └─ NO  → rotate

Signal priority

HIGH
  working credential
  writable privileged object
  exploitable AD edge
  privileged scheduled execution
  internal service with auth bypass/known creds
  exact vulnerable configuration
      → pursue immediately

MEDIUM
  exact version + plausible PoC
  backup/config/source disclosure
  unusual internal listener
  interesting group/privilege with unclear path
      → validate quickly

LOW
  scanner-only CVE hit
  exploit missing prerequisites
  generic "old version"
  repeated fuzzing with no evidence
  exotic CTF idea unsupported by observations
      → park

C0.5 RELIABILITY FILTER

BEFORE RUNNING A TECHNIQUE:
  1. prerequisite proven?
  2. exact build/config known?
  3. privileged trigger reachable?
  4. action exam-compatible?
  5. expected success signal known?

YES → execute
NO  → enumerate/validate first

Fast labels:

✓ = try early when prerequisite matches
△ = fallback / needs stronger validation
! = last resort
⚠️ = OffSec restriction applies
❌ = do not use on the exam

Search [FALSE-POSITIVE] before spending >10 minutes on a weak hypothesis.

C13.5 OUTPUT TRIAGE — BEFORE SWITCHING TOOLS

Search: [OUTPUT:TRIAGE]

2026 passer pattern: missed information in tool output can cost more time than missing another tool. Classify the failure before changing syntax, frameworks or attack paths.

TIMEOUT / NO ROUTE
  → reachability, VPN, pivot, route or firewall path
  → says nothing about credential validity

CONNECTION REFUSED
  → host/path answered but nothing is listening on that port

TLS / CERT / REDIRECT / WRONG HOST
  → hostname, SNI, vhost, scheme or certificate-name problem

401 / LOGON_FAILURE / PREAUTH_FAILED
  → presented identity/secret was rejected
  → check local-vs-domain form and secret provenance once

403 / ACCESS_DENIED / LOGON-TYPE DENIED
  → authentication may be valid; authorization/right is missing

UNKNOWN OPTION / IMPORT / USAGE ERROR
  → local tool/build problem
  → read installed --help before abandoning the hypothesis

EMPTY SMB / LDAP / WEB ENUMERATION
  → first verify share/base DN/filter/Host header/path/scope
  → "empty" is not automatically "nothing exists"

AUTH SUCCESS WITHOUT ADMIN SIGNAL
  → authentication only
  → prove share access / WinRM / RDP / admin execution separately

30-second output micro-loop

1. Copy the exact error/status.
2. Name the failing layer: network → name/TLS → authentication → authorization → parser/tool.
3. Use one native/manual truth check.
4. Correct the proved cause and retry the SAME hypothesis once.
5. New evidence? continue. Same result? record it and rotate.
